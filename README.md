# Filipe Meltzer — Architecture Portfolio

The digital portfolio of Filipe Meltzer, Architect & Urbanist.
A static website — plain HTML, CSS and a little JavaScript, no frameworks — built by a
small Node script and published with GitHub Pages.

**Live site:** https://filipeidea.github.io/Portfolio/

## How it works

All pages are generated as complete HTML by `tools/build.mjs`, so every text, image and
link is readable without JavaScript (search engines, LinkedIn link previews, screen readers,
slow connections). `assets/js/app.js` only adds interaction: the mobile menu, the project filter, the image viewer and tap support for the map and typology lists. If it fails, the site still works.

Every push to `main` runs `.github/workflows/pages.yml`, which builds the site and
publishes it. Nothing has to be built by hand to publish.

```
assets/
  data/projects.js   ← PROJECTS: all project content (edit this)
  data/facts.js      ← PROFILE: experience, awards, publications, figures, contact (edit this)
  data/images.js     image sizes, generated by tools/build_images.py (do not edit)
  img/<project>/     optimised WebP images in several widths
  draw/              Sketchbook drawings and their time maps (tools/build_draw.py)
  og/                1200×630 share images for link previews (tools/build_og.py)
  docs/              downloadable CV (PDF)
  css/style.css      all styling — colours and typefaces are variables at the top
  js/app.js          interaction only
tools/
  build.mjs          builds the site into _site/ (also holds the Sketchbook content)
  build_images.py    turns original images into optimised WebP files
  build_og.py        makes the link-preview images
  edit_cv_pdf.py     corrections made inside the exported CV PDF (see below)
  fonts/             TeX Gyre Heros Bold (Helvetica-compatible, open licence) used by edit_cv_pdf.py
```

Generated pages: `index.html`, `projects/<slug>.html` (one per project), `sketchbook.html`,
`profile.html`, `recognition.html` (awards and press), `resume.html`, `404.html`, `sitemap.xml`, and `project.html`, which forwards
old `project.html?p=<slug>` links to the new addresses.

## Edit content

- **Projects** — `assets/data/projects.js`. The comment at the top explains every field and the
  English names used for design stages. Leave a field `null` to hide it. The order of the list
  is the order on the home page. Open questions are marked `// CONFIRM:`.
- **Profile, résumé, figures, contact** — `assets/data/facts.js`. The `ledger` lists every project
  since 2021 (from the project spreadsheet); the home page figures, the typology table and the
  map on the Profile page are all computed from it. Add a project there and they update.
  New cities also need a point in `mapPoints` (position in % on the map image `América.png`;
  the comment there gives the formula from latitude/longitude). Cities too close to tell apart
  share a `group` (one dot, one card).
- **Recognition page** — `awards`, `publications` and `features` in `facts.js`.
- **Sketchbook** — the `SKETCHBOOK` list in `tools/build.mjs` (chapters and drawings). Each drawing
  draws itself while the page scrolls: its caption steps and the parts of the drawing each step
  covers are in `tools/draw.json`; after changing it run `python3 tools/build_draw.py`
  (Python 3 with Pillow, NumPy, SciPy and scikit-image), which writes `assets/draw/` and
  `assets/data/draw.js`.

You can edit these files directly on github.com (pencil icon → *Commit changes*); the site
rebuilds and updates in about a minute.

## Portuguese version

`tools/i18n.mjs` (run automatically at the end of `tools/build.mjs`) writes a Portuguese copy of
every page into `_site/pt/`, with a language switch in the header and `hreflang` links. Each
English text on the site is looked up in `tools/pt.json` (`"English": "Português"`). After you
change or add a text, run `node tools/build.mjs`: the build reports how many texts have no
translation yet, and `node tools/i18n.mjs --todo` lists them in `tools/pt-todo.json`.
Add their translations to `tools/pt.json` and build again.

## Visual rules

Pure white background on every page; near-black text; the CV blue as the only supporting
colour, used sparingly (big numbers, links on hover, active states); navy only in the footer.
Two typefaces: Archivo (sans, main) and Newsreader (serif, upright, labels and data), no italics.
Moderate type sizes; no all-caps text (capitals only where the language requires them, as in acronyms). The home page opens with a static composition of three project images
(`OPENING` in `tools/build.mjs`), never a slideshow. Colours and fonts are CSS variables at the
top of `assets/css/style.css`.

## Preview locally

Requires Node 18+.

```
node tools/build.mjs
python3 -m http.server 8000 -d _site
```
then open http://localhost:8000.

## Add images

1. Add a line to `MANIFEST` in `tools/build_images.py`, e.g.
   `"new-project/facade": ("S", "folder/original-file.jpg"),`
2. Run (Python 3 with Pillow):
   `python3 tools/build_images.py "<source portfolio folder>" "<crops folder>"`
   This writes `assets/img/new-project/facade-640.webp`, `-1280.webp`, `-2000.webp` and updates
   `assets/data/images.js`. Originals are never modified.
3. Use `"new-project/facade"` as an image key in `projects.js`.
4. For a new project, run `python3 tools/build_og.py` to make its link-preview image.

## Publishing settings

In the repository, **Settings → Pages → Source** must be **GitHub Actions** (already set).
Paths inside the site are relative; the public address `https://filipeidea.github.io/Portfolio/`
is set once in `SITE_URL` at the top of `tools/build.mjs` (used for canonical and share links).
If a custom domain is added later, change `SITE_URL` and the `<base href>` used for `404.html`.

## CV (PDF)

`assets/docs/Filipe-Meltzer-CV.pdf` is the CV exported from InDesign on 10 Oct 2026, corrected by
`tools/edit_cv_pdf.py` (eight years, no "Passionate…" sentence, email, Iguatemi 306 at 49,811 m²,
492,000+ m² and typology areas from the project spreadsheet, Balneário Camboriú on the map,
clickable links, metadata). The original fonts and
layout are kept. **Make the same changes in the InDesign source** so the next export already
contains them; after that, the next PDF can be copied here directly.
